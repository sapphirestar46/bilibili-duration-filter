# B站动态首页 · 视频时长筛选

> 一个零依赖的单文件 Tampermonkey 用户脚本：在 B 站动态首页注入**双滑块时长筛选条**，按视频时长过滤动态卡片。纯前端实现，不改任何请求。

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](#许可证)

---

## 项目简介

B 站动态首页把「视频投稿」和图文、专栏、追番混排在一起，长视频、短视频、纯文字动态交替出现，想找「十分钟左右」或「一小时以上」的内容只能一条条滑。

本项目在动态列表顶部注入一条筛选栏，读取每条动态里视频封面下方已有的时长文本（`.duration-time`），用双滑块设定区间后直接隐藏不匹配的卡片。它**只操作页面上已经渲染出来的 DOM**：不拦截 XHR、不改接口、不上传任何数据，停用脚本即完全复原。

- 运行时产物只有 1 个文件，无第三方库、无构建步骤。
- 支持亮色 / 暗色主题、键盘操作、SPA 与滚动加载。
- 附带一个可离线双击打开的仿真页 [`demo/demo.html`](demo/demo.html)，用来在不登录 B 站的情况下试用和验收。

## 功能特性

| 功能 | 说明 |
| --- | --- |
| 双滑块时长区间 | 对数刻度，定义域 `0 秒 ~ 3 小时`，右端 = 不限；两端互不交叉 |
| 7 个预设按钮 | 不限 / ≤1分钟 / 1–5分钟 / 5–10分钟 / 10–30分钟 / 30–60分钟 / ≥1小时，当前生效项高亮 |
| 启用开关 | 一键停用，所有动态立即恢复显示（`Alt + Shift + D` 同效） |
| 仅显示视频投稿 | 可选开关，默认**关闭**；开启后隐藏纯文字、专栏等非视频动态 |
| 自动加载更多 | 可见视频不足 2 条时按 2 秒节流向下滚动触发原生加载，最多 6 轮 |
| 实时计数 | 显示 `显示 x / y`；无匹配结果时计数变粉高亮，提示当前区间过窄 |
| 增量重扫 | MutationObserver 监听列表变化，滚动加载的新动态自动参与筛选 |
| 未知时长不误伤 | 视频但有解析不到时长（如转码中）时保留显示 |
| 状态持久化 | 开关、区间、选项、收起状态写入 GM 存储 / `localStorage` |
| 收起 / 展开 | 折叠筛选主体只留标题行，状态持久化 |
| SPA 自愈 | Tab 切换、Vue 重渲染后若筛选条被移除会自动重挂载 |
| 调试钩子 | `window.__BDDF__` 提供 `setRange` / `getStats` / `parseDuration` 等接口 |

### 快捷键

| 操作 | 效果 |
| --- | --- |
| `Alt + Shift + D` | 切换筛选启用 / 停用（在输入框内不触发） |
| `←` / `→` | 焦点在滑块上时，步进 1 分钟 |
| `PageUp` / `PageDown` | 步进 5 分钟 |
| `Home` / `End` | 跳到区间两端（`End` = 3 小时，即不限侧） |
| 双击滑块 | 单独重置该端（min → 0，max → 不限） |

## 安装方式

### 方式一：Tampermonkey（推荐）

1. 在浏览器中安装 [Tampermonkey](https://www.tampermonkey.net/) 扩展。
2. 点击扩展图标 →「添加新脚本」。
3. 删除编辑器中的模板代码，把 [`bilibili-dynamic-duration-filter.user.js`](bilibili-dynamic-duration-filter.user.js) 的**全部内容**粘贴进去。
4. `Ctrl + S` 保存，确认脚本处于启用状态。
5. 打开 <https://t.bilibili.com/>（或 `https://www.bilibili.com/` 根路径），筛选条会出现在动态列表 Tab 栏正下方。

也可以直接把 `.user.js` 文件拖进浏览器窗口，Tampermonkey 会弹出安装页。

### 方式二：本地试用（demo 页面）

无需安装扩展，直接双击 [`demo/demo.html`](demo/demo.html)：

1. 页面顶部有说明区和「加载用户脚本」按钮，点击后它通过相对路径 `../bilibili-dynamic-duration-filter.user.js` 动态插入 `<script>`。
2. 部分浏览器在 `file://` 协议下会拦截本地脚本加载；若按钮提示失败，改用上面的 Tampermonkey 方式，或在本目录起一个静态服务器后访问（例如 `npx serve .` 后打开 `/demo/demo.html`）。
3. 页面里的「模拟加载更多」按钮会追加 3 条新动态（含 1 条 `05:30` 视频），用来观察 MutationObserver 是否自动重新筛选。

> 说明：用户脚本在真实站点上只对 `t.bilibili.com` 与 `www.bilibili.com` 根路径生效；考虑到离线演示的需求，它对 `file://` 页面也放行（仍要求页面上存在 `.bili-dyn-list__items` 锚点）。因此在本地双击打开 demo 时脚本可以正常挂载并提供筛选条。

> 演示页本身**不包含任何筛选逻辑**：它只复刻 B 站真实的 DOM 结构与配色，所有隐藏 / 显示行为都来自用户脚本。这也是它可作为「脚本是否正常识别页面结构」的回归样例的原因。

## 使用说明

筛选条位于动态列表 Tab 栏（全部 / 视频投稿 / 追番追剧 / 专栏）下方，滚动时吸顶显示。

- **拖动双滑块**：左滑块为最短时长、右滑块为最长时长，区间为**闭区间**。刻度是对数映射，短视频区间更容易精细控制；拖到最右端表示「不限」。两端滑块不会交叉。
- **点击轨道**：在轨道任意位置点击，就近移动较近的那个滑块。
- **预设按钮**：点一下即应用对应区间，当前匹配的预设会高亮；「不限」恢复全区间。
- **启用开关**（标题右侧的拨动开关）：关闭后不做任何隐藏，等价于临时停用。
- **仅显示视频投稿**：默认关闭。开启后，纯文字、专栏、图文类动态会被一并隐藏，列表只剩视频卡片。
- **自动加载更多**：默认开启。当筛选后可见视频少于 2 条且页面还没到底时，会以约 2 秒一帧的节奏自动向下滚动触发 B 站自己的「加载更多」，最多连续 6 轮，避免刷屏式请求。
- **重置**：恢复为「启用、`0 ~ 不限`、不勾选仅视频」，并清空隐藏状态。
- **收起 / 展开**：只保留标题行，适合小屏或想让列表更干净时使用。
- **双击滑块**：把该端恢复默认（左端 0、右端不限）。
- **Tampermonkey 菜单**：油猴图标菜单里还有「启用/停用时长筛选」「重置筛选范围」两项，效果与页面上一致。

筛选条右侧会显示 `显示 x / y`，其中 `x` 是当前可见动态数、`y` 是列表中动态总数。若一条都不剩（例如 `0 / 12`），计数会变成粉色高亮——此时放宽区间或关掉「仅显示视频投稿」即可。

### 时长与边界规则

- 时长解析支持 `mm:ss`（如 `03:21`）与 `h:mm:ss`（如 `1:12:30`），小时位不补零，也支持超过 24 小时。
- 分、秒必须落在 `0–59`，否则视为非法（例如 `1:60` 解析失败）。
- 视频卡片但取不到合法时长（封面时长还没渲染、转码中）→ **保留显示**，不做猜测。
- 手动输入非法值不会发生，滑块本身只接受合法整数秒。

## 实现原理

```text
页面已有的 DOM ──读取──▶ .bili-dyn-list__item + .duration-time
        ▲                              │
        │                              ▼
   MutationObserver ◀──重扫──  区间判定 [min, max]
        │                              │
        └──────── 列表变化 ──────  加/去 .bddf-hidden
```

1. **定位**：解析 `.bili-dyn-list__items` 下每个 `.bili-dyn-list__item`，在其中查找**第一个** `.duration-time` 的文本，用纯函数 `parseDuration()` 转成秒；没有则记为 `null`。
2. **判定**：时长在闭区间 `[min, max]` 内 → 显示，否则隐藏；取不到时长的视频项一律显示；非视频项由「仅显示视频投稿」决定。停用状态下全部显示。
3. **隐藏**：只给该 `.bili-dyn-list__item` 加自定义类 `bddf-hidden` 与属性 `data-bddf-hidden="1"`，配套一条 `display: none` 样式。**不移动、不删除、不重建 B 站原有节点**，所以停用或卸载脚本后页面完全恢复原状。
4. **重扫**：列表容器的 `MutationObserver` 感知滚动加载与 SPA 重渲染，变更后用 `requestAnimationFrame` 合并成一次批量重扫；重复扫描是幂等的，不会重复插入 UI。另有低开销兜底轮询，以及检测筛选条被 Vue 移除后的自动重挂载。
5. **不碰网络**：脚本不拦截 `fetch` / XHR、不修改 B 站接口参数、不注入任何远程资源。所谓「筛选」纯属渲染层显隐，因此不会减少请求量，也不会影响 B 站自己的加载逻辑；唯一的副作用是「自动加载更多」会在需要时模拟滚动，触发 B 站原生的加载行为（有节流与轮数上限）。

### 存储

优先使用 `GM_getValue` / `GM_setValue`，不可用时回退 `localStorage`，再失败则退化为内存存储（仅本次会话有效）。存储异常一律静默处理，不会打断页面。使用的 key：

| key | 类型 | 默认值 |
| --- | --- | --- |
| `bddf.enabled` | boolean | `true` |
| `bddf.min` | number（秒） | `0` |
| `bddf.max` | number / `"Infinity"` | `Infinity` |
| `bddf.onlyVideo` | boolean | `false` |
| `bddf.autofill` | boolean | `true` |
| `bddf.collapsed` | boolean | `false` |

### 调试接口

页面控制台可访问 `window.__BDDF__`（脚本挂载后可用，重新挂载不会更换引用）：

```js
__BDDF__.version;              // '1.0.0'
__BDDF__.setRange(60, 300);    // 只看 1–5 分钟
__BDDF__.getRange();           // { min: 60, max: 300 }
__BDDF__.setEnabled(false);    // 临时停用
__BDDF__.getStats();           // { total, videos, visible, hidden, unknown }
__BDDF__.parseDuration('1:02:03'); // 3723
__BDDF__.destroy();            // 移除 UI、样式与所有观察器
```

## 已知限制

- **B 站改版即可能失效**：脚本依赖 `.bili-dyn-list__item` / `.bili-dyn-card-video__cover-shadow .duration-time` 等页面类名。一旦前端重构类名或把时长改为图片、Canvas 渲染，筛选会失效（通常表现为计数正常但筛选不生效，或全部按「未知时长」放行）。失效时请提 issue 并附上当时的 DOM 结构。
- **只匹配两个真实站点入口**：`https://t.bilibili.com/*`（全路径）与 `https://www.bilibili.com/` 根路径（含 query）。个人空间、分区页、搜索页等其它带动态流的位置不会注入。此外为支持离线演示，`file://` 页面也会放行（仅当页面上存在动态列表锚点）。
- **统计范围是「当前已渲染」的动态**：`显示 x / y` 只统计列表里现有的 `.bili-dyn-list__item`。被 B 站折叠、被其它插件或广告拦截规则隐藏、以及尚未加载出来的动态都不计入，因此与「总共有多少条」不是一回事。
- **被屏蔽 / 折叠动态影响自动加载判定**：自动加载依据「可见视频 < 2」触发，若可见项因其它原因变少，可能更积极地滚动加载；反之若折叠项占位，可能提前停止。
- **时长未知的视频不会隐藏**：这是刻意的保守策略，代价是在「只看短视频」时可能混入少量长视频。
- **不改变内容分发**：筛选只影响显示，不改变 B 站的推荐与请求；关闭「自动加载更多」即可完全不影响滚动加载行为。
- **非官方脚本**，无法保证与 B 站未来版本的兼容性，也不对使用后果负责。

## 开发与测试

```bash
# 安装测试依赖（jsdom 等）
npm install

# 运行 jsdom 集成测试（node --test）
npm test

# 用本机 Chrome/Edge 无头打开 demo、注入脚本、跑交互断言并截图
node tools/screenshot.mjs          # 截图输出到 tools/screenshots/
node tools/screenshot.mjs --headed # 需要肉眼看时用有头模式
```

- `tools/` 是一个独立的小包（`playwright-core`，复用系统已安装的 Chrome，不额外下载浏览器），首次使用需在 `tools/` 内 `npm install`；也可用 `CHROME_PATH` 环境变量指定浏览器路径。
- 测试的 fixture 由测试文件自行构造，**不依赖** `demo/demo.html`，所以改动演示页不会影响测试结论。
- 用户脚本本身是纯 ES2020 单文件，无构建步骤；改完直接 `node --check bilibili-dynamic-duration-filter.user.js` 做语法校验。
- 只想跑某一组用例时可用 `npm run test:parse` / `npm run test:filter` / `npm run test:lifecycle`，分别对应时长解析、筛选语义与生命周期（观察器、`destroy()`）测试。
